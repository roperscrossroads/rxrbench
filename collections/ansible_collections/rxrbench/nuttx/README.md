# rxrbench.nuttx

Apache NuttX devices as bench devices, through NSH. The plugin brings one family, `nuttx_nsh`:
known by what it answers to `uname -a` (release, the build's commit and time, the machine), and
spoken to through NSH, which the broker reads as it reads Zephyr's shell. Its configuration is
files: the board's storage is mounted first, the declared files are written through the shell,
and the ones named as secrets never reach the broker's log or a task's output. The module is
`nuttx_files` (`ansible-doc rxrbench.nuttx.nuttx_files`). The plugin contract it fills in:
[docs/PLUGINS.md](../../../../docs/PLUGINS.md).

The simulated board is NuttX's own `sim:nsh` ([docs/SIMULATED.md](../../../../docs/SIMULATED.md)),
which speaks on its standard streams: the bench makes a pty for it (`sim_console: stdio` in the
registry). Its storage is a host directory mounted with hostfs, where a real board would mount
a flash file system. Its reboot is a power-off; the bench starts a simulated board again.

## A board's declaration

```yaml
firmware: {family: nuttx_nsh, image: nsh}
nuttx:
  storage: {at: /data, type: hostfs, source: /where/the/host/keeps/it}   # mounted first
  files:
    /data/psk: 9f1c…                 # one word each: the shell splits on whitespace
    /data/cert: MIIB…
    /data/name: nb1
  secrets: {psk: /data/psk, cert: /data/cert}   # which files are secrets, by kind
  facts: [/data/name]                           # what `just facts` reads
```

## Images

`just sim-nuttx-build` builds `nsh` and `nsh-b` (another prompt) with `tools/nuttx_sim.py`, from
a directory holding `nuttx/` and `apps/` (`RXRBENCH_NUTTX_WORKSPACE`). It stages each
executable with a manifest recording what the image answers to `uname -a`, which is how a board
running it is told apart from another build. NuttX's configure wants `kconfiglib` in the
workspace's own venv (`.venv`); `kconfig-tweak` is supplied by the tool when the host lacks
it. The builds take the console in single-character mode: the sim's default DMA mode holds
every 256th byte typed until the next one.

## On hardware

A NuttX image has been written to an RP2040 board and read back by core's `picoboot` route.
Configuration over NSH runs on the sim board only: on an RP2040 the flash file system lives
inside the image, so a file written would go with the next flash.
